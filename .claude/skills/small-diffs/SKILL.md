# small-diffs — меняй строки, а не файлы

Перегенерация целого файла ради одной функции — это сотни лишних токенов
вывода и риск сломать то, что работало. Точечная правка дешевле и безопаснее.

## Правила

### 1. Редактируй, не переписывай
Используй точечную замену строк (Edit), а не полную перезапись (Write).
Write оправдан только когда:
- файл создаётся с нуля;
- меняется большая часть файла (грубо — больше половины).

### 2. Минимальный объём изменения
- Трогай только строки, относящиеся к задаче.
- Не переформатируй файл «заодно», не меняй кавычки/отступы вне задачи —
  это раздувает дифф и вывод.
- Не переименовывай несвязанные переменные «чтобы красивее».

### 3. Сохраняй стиль окружения
Пиши так, как написан соседний код: те же отступы, нейминг, кавычки, плотность
комментариев. Тогда правка короче (нечего объяснять) и не вызывает «причёсываний».

### 4. Уникальный якорь для замены
При точечной замене бери ровно тот фрагмент, который нужно поменять, плюс
минимум контекста для уникальности — не весь блок.

### 5. Одна правка — одно изменение по смыслу
Несколько несвязанных изменений лучше как отдельные точечные правки, чем одна
огромная перезапись. Легче проверять, легче откатывать.

## Плохо → хорошо

```diff
# Задача: поменять таймаут с 3000 на 5000

# ПЛОХО: перезапись всего файла (200 строк вывода)
Write config.ts  # ...весь файл целиком...

# ХОРОШО: точечная замена (1 строка)
- timeout: 3000,
+ timeout: 5000,
```

## Анти-паттерны

- ❌ Перезаписывать файл целиком ради мелкой правки.
- ❌ Массовый авто-реформат вместе с содержательной правкой.
- ❌ «Заодно» чинить несвязанные вещи в том же диффе.
- ❌ Перечитывать файл после правки «для проверки» (редактор бы упал при ошибке).
