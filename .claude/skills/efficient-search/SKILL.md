# efficient-search — находи, а не пролистывай

Чтение файлов «чтобы поискать глазами» — одна из самых дорогих привычек.
Поиск возвращает только релевантные строки, а не весь файл.

## Что чем искать

| Задача | Инструмент | Почему дёшево |
|--------|-----------|----------------|
| «где определён/используется X» | Grep (по содержимому) | вернёт строки, не файлы целиком |
| «где лежит файл по имени/маске» | Glob | только пути, без содержимого |
| «что вообще в этой области» | Grep с `-l` → точечный Read | сначала список, потом нужное |

## Правила

### 1. Сначала найди место, потом читай окрестность
```
# плохо
Read src/services/auth.ts        # 600 строк в контекст ради одной функции

# хорошо
Grep "function login" src/        # → auth.ts:42
Read src/services/auth.ts:30-70   # только нужный блок
```

### 2. Сужай поиск фильтрами
- По типу/расширению файлов (`glob: "*.ts"` / `type: "ts"`).
- По папке (ищи в `src/`, а не в корне со всем `node_modules`).
- Точным паттерном, а не слишком общим словом, которое даст сотни совпадений.

### 3. Выбирай правильный режим вывода
- Нужны **пути** файлов → режим «files only» (самый дешёвый).
- Нужно **сколько раз** встречается → режим «count».
- Нужны **строки** → режим «content», и добавляй контекст (`-C`) только если он
  правда нужен.

### 4. Не дублируй поиск
Если уже нашёл, где лежит символ — не ищи его снова через пару шагов. Держи
найденное в уме.

## Анти-паттерны

- ❌ Читать директорию файл за файлом, чтобы «осмотреться».
- ❌ Grep по одной букве или слишком общему слову → сотни совпадений в контекст.
- ❌ Запрашивать большой контекст (`-C 50`) там, где хватит пары строк.
- ❌ Искать в корне, когда известно, что код в `src/`.

## Мини-рецепты

```
# найти, где экспортируется компонент
Grep "export.*Dashboard" --type ts --output files

# посчитать, насколько распространён паттерн (стоит ли рефакторить)
Grep "useEffect" src/ --output count

# найти конфиг по маске
Glob "**/*.config.{ts,js}"
```
