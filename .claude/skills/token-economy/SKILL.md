# token-economy — экономь токены на каждом шаге

Главный скилл коллекции. Задаёт привычки, которые снижают расход токенов на
любой задаче. Остальные скиллы — углубление отдельных пунктов.

## Откуда берётся расход

1. **Контекст (вход):** всё прочитанное — файлы, вывод команд, история —
   занимает токены и тарифицируется на каждом шаге диалога.
2. **Генерация (выход):** каждый символ кода и текста, который ты выдаёшь.
3. **Переделки:** ошибся → переделал → снова прочитал → снова выдал. Самый
   дорогой класс трат, потому что умножает первые два.

## Правила

### 1. Читай точечно, а не целиком
- Знаешь нужный диапазон — читай только его (`offset`/`limit`), а не весь файл.
- Не загружай большие файлы «чтобы было». Сначала найди место (см.
  `efficient-search`), потом прочитай окрестность.
- Не читай файл, который только что отредактировал, «чтобы проверить» —
  редактор сам бы упал при неудаче, состояние файла уже известно.

### 2. Ищи, а не пролистывай
- Для «где определён X» — поиск по содержимому (Grep), не чтение папок подряд.
- Для «где лежит файл» — поиск по имени (Glob).
- Подробности и шаблоны — в скилле `efficient-search`.

### 3. Делай независимые вызовы параллельно
Если вызовы не зависят друг от друга — отправляй их одним пакетом, а не по
очереди. Меньше раундов = меньше повторно прогоняемого контекста.

```
# плохо: три отдельных шага, контекст растёт между ними
read A → (ответ) → read B → (ответ) → grep C

# хорошо: один пакет
[read A, read B, grep C]
```

### 4. Маленькие точные правки
Меняй только нужные строки, не переписывай файл целиком. См. `small-diffs`.

### 5. Попадай с первого раза
- Перед правкой убедись, что понял требование. Один уточняющий вопрос дешевле,
  чем три цикла переделок.
- Не угадывай API/имена — проверь поиском один раз.

### 6. Короткие ответы
Пользователю нужен результат, а не пересказ процесса. См. `concise-replies`.

### 7. Не раздувай код
Простой минимальный код дешевле и сейчас (меньше вывода), и потом (меньше
правок). См. `lean-code`.

## Анти-паттерны (так не надо)

- ❌ «Прочитаю весь репозиторий, чтобы понять контекст» — читай по мере нужды.
- ❌ `cat` целого файла ради двух строк — используй поиск + точечное чтение.
- ❌ Повторное чтение файла после своей же правки.
- ❌ Длинное вступление «Сейчас я сделаю...» перед каждым действием.
- ❌ Перегенерация всего файла ради изменения одной функции.

## Быстрый чек-лист перед действием

- [ ] Мне правда нужен весь этот файл — или хватит диапазона/поиска?
- [ ] Эти вызовы можно отправить одним пакетом?
- [ ] Я не перечитываю то, что уже знаю?
- [ ] Мой ответ короче, чем мог бы быть?
